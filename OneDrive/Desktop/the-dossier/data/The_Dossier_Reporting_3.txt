1. PROJECT DESCRIPTION
The Dossier is a simple rental-safety application for people looking for a home, shared flat, or roommate in Mumbai. It helps a user compare a locality, find a possible roommate, check a rental agreement, prepare questions for the landlord, record the condition of the home, track shared costs, and keep payment or repair evidence.

The project currently focuses on Mumbai because it is a useful starting location with high rent, many students and working professionals, long travel times, shared flats, broker dealings, and common problems related to deposits, society rules and rental agreements. The project can later be expanded to other Indian cities.

2. REAL-LIFE PROBLEM
People often make rental decisions quickly. They may pay a token amount before checking the exact flat, trust verbal promises, misunderstand the rent split, fail to record old damage, or sign an agreement without understanding the important parts. Later, disputes may happen over deposits, repairs, visitors, maintenance, society rules, rent increases or the return of keys.

The Dossier addresses this by bringing the main rental checks into one place. It does not claim that a property is legally safe, verify ownership, provide a valuation, or replace a lawyer. It is a first-check and evidence-organising tool.

4. APPLICATION MODULES
A. Dashboard
Shows the purpose of the application and directs the user to the most useful next action.

B. Scan Contract
Accepts a rental agreement and checks it using a transparent rulebook. It highlights possible issues such as deposit deductions, termination, liability, indemnity, automatic renewal, repairs and governing law. The user sees the matching wording and a simple explanation.

C. Locality Decision Map / Property Guide
The map uses selected Mumbai locality centres for comparison. Current sample localities are Andheri West, Powai, Vikhroli, Goregaon and Thane. The guide shows indicative rent and room-share ranges, transport, commute notes and practical signals. It also includes renting and buying checklists.

D. Find Roommates
Shows sample profiles that can be filtered by locality, budget and move-in period. A profile contains a first name, area, monthly share, move-in period, work or college area, room type, lifestyle description and sample fit percentage.

E. Tenant Workspace
Contains a before-signing checklist, questions to ask the landlord, a copy-ready message, move-in condition record, move-out handover checklist, shared-cost calculator, repair record and payment/receipt record.

F. My Rental Records
Keeps the existing scan history and review summaries. Future work will extend this into a complete record of agreements, receipts, repairs, photos and deposit status.

5. SAMPLE DATA AND PERMISSIONS
The names used in the current Roommate Finder are random demo names: Arjun, Neha, Rohan and Sameer. The sample locality data uses Mumbai areas and the sample rent ranges are illustrative estimates created only for demonstrating the interface.

The project does not currently use real student profiles, real landlord profiles, live property listings, verified rent statistics or live user accounts. Real property listings, names, photos, maps, market rates or data from websites must not be copied or used without permission. A real release would need consent, privacy controls, terms of use, reporting tools, source attribution and permission from data providers. It should also show the source, date and confidence level for every market or locality insight.

The map pins are locality centres for comparison. They are not exact property locations, property boundaries or proof of availability.

7. SYSTEM WORKFLOW
User selects a Mumbai locality → reviews the locality decision snapshot → applies budget and commute filters → opens roommate matches → sends a safe connection request → uploads a rental agreement → receives plain-language findings → asks the landlord questions → records move-in condition, payments and repairs → completes move-out and deposit follow-up.

8. IMPLEMENTATION DETAILS
The project uses a transparent rule-based method for agreement review. Each rule contains a clause type, risk level, search pattern, explanation and recommendation. Extracted agreement text is compared with these rules. When a pattern is found, the matching wording is shown to the user.

The Property Guide stores the selected locality in Streamlit session state and passes it to the Roommate Finder. The current application uses local demonstration data for map and roommate screens. Existing SQLite storage continues to save agreement reviews. Workspace records are currently interactive prototype records and need permanent database tables in the next phase.
